# Baton Partners — 企業サイトの作り方（テンプレート運用ルール）

エボルグ版（`/evorg/`）が社長承認済みの基準。**2社目以降は、これと同じ品質・構成で作る。**

## 1社＝5ページ（固定）

| ページ | URL | 中身 |
|---|---|---|
| トップ | `/<slug>/` | WebGLのステージ（集める→つなぐ→決める）、公式バッジ、流れる帯、課題、看板機能、数字、利用企業、取り組み・サービス・記事への導線 |
| 取り組み | `/<slug>/about/` | どんな会社か（Batonでいうプロフィール）。会社公式サイトの表現を使う |
| LP（SEO記事） | `/<slug>/insights/<記事>/` | 見込み客の悩みから入る記事。最後にサービスと「話してみる」へ |
| サービス | `/<slug>/service/` | 商品説明。サービス公式サイトの表現を使う |
| 話してみる | `/<slug>/contact/` | 公式LINE追加 → 4〜5問のアンケート（資料・URLの添付は任意）→ Music Japanが確認 → 先方へ概要を事前共有 → 双方了承でLINEグループ |

## 作る手順

1. **本家（会社・サービスの公式サイト）を必ず先に読む。** 文言は公式の表現を最優先。独自のキャッチは作らない。
   読めなかった内容は断定しない。社長の調査メモ（GPTなど）は、本家と矛盾しない範囲で取り込む
2. ロゴを社長からもらい、背景を透過して `public/partners/<slug>/` に置く（実寸を `logoSize` に）
3. ロゴから色を取り、`brand.primary / accent` と WebGL の `scene`（a=点 / b=輪 / match=重なり）を決める
4. `src/partners/evorg.ts` をコピーして `src/partners/<slug>.ts` を作り、`src/partners/index.ts` に登録。`.gitignore` に `/<slug>/` を足す
5. 確認：`npm run build` → 375 / 390 / 430 / 1440 / 1920px × 5ページで、横はみ出しゼロ・コンソールエラーゼロ・見出しの泣き別れなし
6. コミット → `claude/` ブランチへプッシュ → Vercel（`baton-partners-demo` プロジェクト）へ本番デプロイ → 外部からURLを開いて確認

## 世界観は企業ごとに作り分ける（使い回し感を出さない）

5ページの骨組み・導線・品質基準は共通。**見た目と演出は、その会社のロゴとトーン＆マナーから決める。**
`world: { theme, scene }` で切り替える。新しい会社の世界観が既存に合わなければ、theme / scene を新しく足す。

| 企業 | theme | scene | 根拠 |
|---|---|---|---|
| エボルグ | editorial（紙・墨・明朝＋イタリック、色のグラデーション） | network（点と線の球体） | 赤と水色のロゴ、人と求人が「つながる」 |
| Central AX | mono（モノクロ・太いゴシック・方眼・四隅のトンボ・黒帯の白抜き） | lattice（立方体の建築模型＋走査線＋光の柱） | 黒一色の四角い枠のロゴ、「現場」「実装」 |
| DPパートナーズ | console（ロゴの箱とトラック：DPの青・空色・オレンジ、等角の方眼、立方体の印、等幅の英字、作業ログの帯） | vault（古いサーバー→新しいサーバーへ移す、レーダーと控えで守る、壊れても保管庫から戻す） | 「サイト引越し屋さん」、保守の考え方「絶対に復旧できる」 |
| Cominka | minka（古民家と縁：朱・墨・生成り、しっぽり明朝＋細身の欧文、麻の葉の地紋、障子の格子、判子、縦書き、「其の一」の番号、暖簾のCTA） | en（検索の札が格子に並び、判子が押され、赤い糸で中央の印に結ばれる） | 社名の由来「古民家」、MISSION「縁を発明する」、赤い角判のロゴ |
| Music Japan（運営・BP-000） | relay（白と墨と日の丸の赤、極太ゴシック＋Big Shoulders の数字＋Jost の細い欧文、ゼッケンの番号、LEDの帯、赤いタータンの4区間、電光掲示板、スタートラインのCTA） | relay（光の点がトラックに降り、レーンが一周描かれ、赤く塗られて走者が走り、バトンが白から赤へ渡る。中央にロゴの赤い輪と点） | ロゴの「赤い輪と点」、サービス名「Baton」 |

- 図解の部品（検索結果の図・事例のグラフ・プロダクトと受賞・MISSION）は `top.serp / cases / product / mission` に入れたときだけ出る。どの世界観でも使える
- 新しい部品のクラス名は、既存の `.ln`（見出しの行）などとぶつけない。ぶつかると見出しが潰れる

- 代表の写真があれば `leader` に入れる（取り組みページに専用セクション、トップにも小さく）。発言は作らない
- ロゴは背景を透過し、黒背景用の白抜き版も作る

## 運営会社のページ（`/music-japan/`・BP-000）

Baton Partners そのものを売るページ。骨組みは同じ5ページだが、次だけ違う（`operator: true`）。

- パートナー企業のカタログ（一覧のカード・件数・ItemList）には並べない。一覧のヒーロー、Baton Partners のヘッダー、フッターから「Baton Partnersとは」で案内する
- 構造化データの会社・代表者は、music-japan.com と同じ `@id`（`#organization` / `#founder`）。全ページ共通の土台（`siteLd`）に、会社・代表者（壁谷友生）・サービス「Baton Partners」のつながりを入れている
- 「話してみる」は、オーナーの指示で予約ページ（TimeRex）で日程を選ぶ形（`contact.booking`）。予約ボタンはこのページにだけ置く。掲載企業のページは今まで通りLINE＋アンケート
- オーナーの指示で、音楽の話・SECOND TAKE・紹介業を始めた経緯は書かない。フッターの「作品」リンクも出さない
- 部品：`top.relay`（4区間）、`top.spotlight`（ミラエラの紹介。数字と掲載企業はミラエラの公表情報だけ、取材の可否は約束しない）、`top.partnerLogos`（掲載了承済みの会社だけ。正式ロゴが届くまでは社名の文字）
- OG画像だけ作り直すとき：`OG_ONLY=music-japan npm run og`

## 文章は、人間の書き手のように

AIっぽい文章は掲載企業の信用を落とす。次を守る。

- 「〜を実現」「〜に寄り添い」「〜を加速」などの定型句、体言止めの連発、3つずつ並べるリズムを避ける
- 抽象語より場面を書く（「業務効率化」→「見積書の下書き」「紙の日報」）
- 文の長さを混ぜる。言い切りと、少し柔らかい言い回しを両方使う
- ダッシュ（——）でつながない。読点と句点で区切る
- 数字・実績は公表済みのものだけ。伝聞は「〜そうです」と書き分ける

## 変えてはいけないこと

- **先方の確認前の企業は `draft: true`**。プレビュー（*.vercel.app）にだけ出て、本番ビルドにはページも一覧も一切含まれない（`src/partners/index.ts`）。
  確認が取れたら draft を外して本番へ。ロゴを仮のワードマークで作った場合は、正式なロゴに差し替えてから外す

- **価格・契約条件はサイトに一切出さない**
- ボタンは「話してみる」。「相談する」「お問い合わせ」は使わない
- 予約カレンダーは置かない（運営会社のページ `/music-japan/contact/` だけは例外。オーナーの指示）。自動マッチングしない。紹介の判断は社長
- 掲載企業へは「相談が1件届いた」通知と受付番号だけ。お客様の個人情報は双方了承までMusic Japanだけが持つ
- 公開先は `https://partners.music-japan.com/<slug>/`（DNSは Cloudflare で `partners` → `cname.vercel-dns.com`、プロキシはオフ）。
  本番ビルドだけ検索に載せる。プレビューとローカルは noindex、`*.vercel.app` は X-Robots-Tag で noindex。止めたいときは `BP_NOINDEX=1`
- 送信先（`VITE_GAS_ENDPOINT`）が未設定のまま公開ドメインで開かれたら、フォームを閉じて公式LINEへ案内する（回答が消えないように）
- 背景は白。書体と装飾は world.theme で決める（editorial は明朝＋Fraunces、mono は太いゴシック＋Archivo）
- 「動きを減らす」設定・WebGL非対応でも、完成形の見た目は崩れないこと

## ロゴ

- Baton（シンプル）：黒い角丸に白と赤の丸、「Baton」Helvetica 500・字間0.16em（`baton/public/favicon.svg`）
- Baton Partners（リッチ）：同じ骨格に、墨のグラデーション・光沢・縁取り・光の輪・渡る弧。「Partners」はFrauncesイタリック＋赤のグラデーション
- 実装は `src/render/logo.ts`（`bpMark` / `bpLogo`）。単体ファイルは `public/brand/`（ビルド時に自動生成）

## 日本語の改行

見出しはBudouXで文節ごとに折り返す。BudouXが割ってしまう語は、データ側で `{取りこぼさずに}` のように波かっこで囲む。
追加した見出しは、必ずスマホ幅で「単語の途中で改行されていないか」を目で確認する。
