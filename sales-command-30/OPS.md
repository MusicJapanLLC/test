# OPS — 営業司令室 30

## 通常運用
- 毎営業日: Slack通知が届いているか確認
- 週1回: 追客遅延件数と失敗実行を確認
- 月1回: 顧客と30分レビュー、不要通知・不足通知・KPI項目を調整
- 自動化フロー変更は月1回の軽微修正まで基本料金内

## 人間の手作業が必要な工程
- 初回ヒアリング
- OAuth承認（顧客本人）
- 営業ルールの最終決定
- 自動化テスト結果の承認
- 顧客への実際の返信・契約判断
- 月次レビュー
- 障害の原因が外部SaaS/API側の場合の問い合わせ

## 障害時対応
### Level 1: 通知遅延・単発失敗
1. Make実行履歴を確認
2. 接続状態を確認
3. APIレート制限・クレジット不足を確認
4. データ欠損がない場合は再実行または次回実行で復旧

### Level 2: OAuth失効・接続切れ
1. 対象フローを停止
2. 顧客へ再認証を依頼
3. テストデータで再接続確認
4. 本番復帰

### Level 3: 誤通知・誤マッピング
1. 対象フロー停止
2. 誤処理範囲を特定
3. データ修正が必要なら顧客確認後に実施
4. 修正後テスト
5. 原因と再発防止を記録

### Level 4: 外部サービス障害
Make / Google / Slack等の障害時は当社がサービス自体を復旧させることはできない。影響範囲を確認し、必要に応じて一時停止・復旧後再開を行う。

## SLAの扱い
v1では24時間有人監視、復旧時間保証、損害賠償付きSLAは提供しない。営業時間内の一次切り分けを基本とする。

## 解約時データ処理
1. 解約日を確定
2. 当社管理の自動化を停止
3. OAuth/接続を解除
4. 当社管理DBの顧客データを契約で定めた期間内に削除
5. 顧客所有Google/Slack/CRM内のデータは顧客が保持
6. 必要ならCSV等で顧客管理データを返却（仕様・工数は契約時に定義）
7. 削除完了を記録

## 原価モデル
原則として、Google Workspace / Slack / Make等の有料アカウントは顧客名義・顧客負担。これにより当社がAPI/SaaS利用料を無制限に抱えない。

当社側の月次変動原価目安:
- App/監視基盤按分: 1,000〜3,000円/社
- AI APIを使う場合: 0〜3,000円/社を上限目安として設計、超過は事前合意
- 月次レビュー30分 + 保守30〜60分: 人件費として内部計上

売上30,000円 - 外部原価3,000〜6,000円 = 粗利24,000〜27,000円/社（人件費前）
外部原価率10〜20%。

初期費用50,000円はヒアリング・構築・テスト工数の回収に充てる。

## 無料依存禁止
Freeプラン限定機能を本番要件にしない。無料枠を検証に使う場合も、本番開始前に必要クレジット・実行頻度・有料化条件を確認する。
